## Usage

```tsx
import { ScrambleText } from "@/components/asciicn/scramble-text";

export function Headline() {
  return (
    <ScrambleText as="h2" glyphs="katakana" className="text-4xl font-bold">
      Decrypting the signal
    </ScrambleText>
  );
}
```

Every character starts on a random glyph from the set, changes `rate` times a second, and settles on its letter after `duration` seconds plus `stagger` seconds per character before it, so the text resolves left to right. Spaces stay spaces.

The final text is always laid out and the scrambling glyph is painted over each letter's slot, centred on it. Nothing the animation does can move the layout, even in a proportional font or with glyphs wider than the letters they cover.

## Notes

- Screen readers get the final text once, from a visually hidden copy. The animated letters are `aria-hidden`. Copying the visible text copies the final string, never the glyphs, because the glyphs are drawn by CSS pseudo-elements.
- With reduced motion, nothing scrambles: the text shows as is.
- `view` plays when the text scrolls into view. Leaving the screen mid-scramble settles every letter at once.
- Katakana and some CP437 glyphs come from a fallback font when the glyph font lacks them. They are centred over each letter, so a wider glyph never pushes its neighbours.
- One `requestAnimationFrame` loop runs while letters are scrambling and stops when they settle. React does not re-render per frame.
