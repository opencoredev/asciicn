## Usage

```tsx
import { UptimeBar } from "@/components/asciicn/uptime-bar";

const days = [
  { date: "2026-10-11", uptime: 1 },
  { date: "2026-10-12", uptime: 0.9962, note: "Elevated latency on writes." },
  { date: "2026-10-13", uptime: 1 },
];

export function ApiStatus() {
  return <UptimeBar label="API" days={days} />;
}
```

Pass one entry per day, oldest first. Each day's status comes from its `uptime`: 99.9% or more is up, 99% or more is degraded, and anything lower is an outage. Set `status` on a day to override that, or `uptime: null` for a day with no data.

Each day is one text column of left half blocks (`▌`, `▖`), so neighbouring days keep a gap without any CSS. The status sets the height as well as the colour: up days fill every row, degraded days three quarters, outages a quarter, and days without data are a single `·`. `rows` sets how many text rows the bars span.

The row shows the last 30 days on narrow screens, 60 from 28rem wide and 90 from 42rem, based on the width of its container. Without `cell`, the glyphs grow until those days fill the row, up to `maxCell`. The bars always span whole text rows. The percentage on the right is the average over every day with data.

## Notes

- Status shows in height as well as colour, so the statuses stay apart for colour-blind readers and in greyscale.
- Each day is a button with a full description, such as "Oct 9, 2026, Degraded, 99.62% uptime". Only one day is in the tab order; the arrow keys, Home and End move between days, and Escape closes the tooltip. Tapping a day shows its tooltip on touch screens.
- Sizing to the row is pure CSS (container query units), so the bar renders on the server at its final size with no layout shift.
- Dates are formatted in UTC, so the server and the browser agree.
